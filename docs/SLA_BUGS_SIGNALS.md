# SLA-баги: каталог сигналов

Краткий каталог **меток на карточках** для согласования: что оставляем, что убираем.

**Полное описание вкладки** (секции, критерии попадания, сортировка, UI, API): **[SLA_BUGS_TAB.md](./SLA_BUGS_TAB.md)**.

Источник правды в коде: `lib/slaBugs/classifySlaBug.ts`, `lib/slaBugs/slaBugMetrics.ts`, `lib/slaBugs/config.ts`.

---

## Как устроено

- На карточке показывается **один** сигнал — с наивысшим приоритетом среди подходящих.
- Сигнал не равен секции: секция (`Брать сейчас` / `Следить` / …) задаёт группировку в сайдбаре, сигнал — метка на карточке.
- **P0–P2:** если ни один сигнал не подошёл — метка **не показывается** (не «Без сигнала»).
- **P3–P4:** если ничего не подошло — может показаться «Без сигнала» в секции «Обычные».

### Приоритет выбора одного сигнала

1. **P3 + «Понизить приоритет»** по правилу 30 дней без повышения HD — всегда `demote` (выше `hd_high` / `hd_low` и т.д.).
2. В секции **«Разобрать»** приоритет у `close_p4` и `demote`.
3. Иначе — первый подходящий из списка (сверху вниз):

```
sharp_growth → growth_24h → save_sla → close_to_upgrade → hd_high →
key_client → sup_priority → hd_medium → hd_low → demote → close_p4 →
no_growth → no_signal
```

### SLA и дедлайн

Если в Tracker нет поля SLA, дедлайн считается от `createdAt`:

| Приоритет | Срок решения |
|-----------|--------------|
| P0 | 1 день |
| P1 | 7 дней |
| P2 | 14 дней |
| P3 | 45 дней (1,5 мес.) |
| P4 | 180 дней (6 мес.) |

## Активные сигналы (13 шт.)

Колонка **Нужно?** — для вашей разметки: ✅ / ❌ / изменить.

| № | Ключ | На карточке | Когда ставится | Нужно? |
|---|------|-------------|----------------|--------|
| 1 | `sharp_growth` | **Резкий рост** | Рост HD за 24 ч **≥ 3** (не считается «первым контактом»: 24h = 1 и hd_count = 1) | |
| 2 | `growth_24h` | **Рост 24ч** | Рост 24h **≥ 2**; или слабый рост (P3: 24h = 1 при hd ≥ 4; P4: 24h = 1 при hd ≥ 3); или умеренный рост 7d (P3: ≥ 3; P4: ≥ 4) | |
| 3 | `save_sla` | **Спасти SLA** | До SLA: **P0 ≤ 24 ч**; **P1 ≤ 3 дн**; **P2 ≤ 7 дн**; **P3 ≤ 14 дн** | |
| 4 | `close_to_upgrade` | **Близко к P↑** | P3: hd **18–20**; P4: hd **8–10**; ключевой клиент: hd **3–4** или **8–9** | |
| 5 | `hd_high` | **HD высокий** | Обычный: hd **8–17**; ключевой клиент: hd **5–9** | |
| 6 | `key_client` | **Ключевой** | Поле или тег ключевого клиента | |
| 7 | `sup_priority` | **Пуш поддержки** | Поле или тег пуша приоритета от поддержки | |
| 8 | `hd_medium` | **HD средний** | Обычный: hd **4–7**; ключевой клиент: hd **3–4** | |
| 9 | `hd_low` | **HD низкий** | Обычный: hd **1–3**; ключевой клиент: hd **1–2** | |
| 10 | `demote` | **Понизить приоритет** | **P3** в секции «Разобрать» или по правилу demote (см. ниже) | |
| 11 | `close_p4` | **Закрыть P4** | **P4** в секции «Разобрать» (кандидат на закрытие) | |
| 12 | `no_growth` | **Нет роста** | hd > 0, но нет значимого роста 24h и 7d | |
| 13 | `no_signal` | **Без сигнала** | Секция «Обычные», hd ≤ 3, нет роста, не «близко к P↑», не ключевой/пуш, не «HD низкий» | |

## Подтипы «Понизить приоритет» (`demote`)

Используются в тултипе сигнала `demote`:

| Ключ | Описание | Критерий |
|------|----------|----------|
| `low_relevance` | Низкая актуальность | P3, hd **1–3**, нет роста 24h/7d, **> 30 дней** с последнего повышения HD (или просрочен SLA), возраст задачи **> 30 дней**; не ключевой, без пуша, не в активной работе, hd < 18 |
| `stale_p3` | Залежавшийся P3 | P3 старше **180 дней**, hd **< 18**, нет роста, последнее повышение HD **> 90 дней** назад; те же блокировки |

## Секции (контекст, не сигналы)

| Секция | Кто попадает (кратко) |
|--------|------------------------|
| **Брать сейчас** | P0–P2 всегда; P3/P4 — по росту HD, SLA, «близко к P↑», ключевой/пуш |
| **Следить** | P3/P4 с умеренным риском (рост, «близко к P↑» без роста, окно SLA 15–21 дн. для P3 и т.д.) |
| **Обычные** | Спокойные P3/P4 без триггеров выше |
| **Разобрать** | P3 — кандидаты на понижение; P4 — кандидаты на закрытие |

---

## Действия на карточке «Закрыть P4» (не сигналы)

При сигнале `close_p4` на карточке показываются кнопки:

| Действие | Тег в Tracker | UI после действия |
|----------|---------------|-------------------|
| Отправить на согласование | `closing_candidate` | «На согласовании» + комментарий в задачу |
| Оставить | `bug_in_progress` | «Оставили» |

Статус задачи в workflow **не меняется** — только тег и (для согласования) комментарий.
