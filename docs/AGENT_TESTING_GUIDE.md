# Руководство по тестированию для агентов (MCP)

## Обзор проекта

**Beer Tracker** — веб-приложение для планирования спринтов по свимлейнам поверх **Яндекс Трекера** или **Jira**. Задачи раскладываются по исполнителям и дням спринта (10 рабочих дней, день — 3 ячейки: `WORKING_DAYS`, `PARTS_PER_DAY` в [`constants/index.ts`](../constants/index.ts)). Провайдер: [ISSUE_TRACKERS.md](./ISSUE_TRACKERS.md).

### Технологический стек

- **Frontend**: Next.js 16, React 19, TypeScript
- **Backend**: Next.js API Routes
- **База данных**: PostgreSQL (позиции задач, цели спринта, доска ретро, снимки задач `issue_snapshots`)
- **Внешние API**: Issue tracker API — Yandex Tracker **или** Jira (мутации, спринты, доски)
- **UI**: Tailwind CSS, Radix UI, dnd-kit (drag-and-drop)

## Где тестировать

| Контур | Адрес | Когда |
|--------|-------|-------|
| Демо на фикстурах | `/demo/planner` | UI планера без логина и трекера. Данные — [`lib/demo/`](../lib/demo/), часы зафиксированы. Состояние живёт в памяти вкладки: перезагрузка страницы возвращает фикстуру. |
| Боевой планер | `/planner/:boardId/sprint/:sprintId?tab=…` | Всё, что пишет в трекер или PostgreSQL: статусы, оценки, перенос в спринт, сохранение позиций после перезагрузки. Нужен логин и подключённый трекер. |

На `/demo/planner` нет аватара и колокольчика уведомлений в шапке, люди на доске — персонажи фикстуры. Тест-кейсы, помеченные **[демо]**, проходят там целиком; остальные — только на боевом контуре.

## Архитектура UI

### Страницы

1. **Выбор доски** (`/select-board`) — список досок организации из трекера. После выбора — переход на `/planner/:boardId/sprint/:sprintId?page=sprints&tab=board` (активный спринт, иначе первый в списке).
2. **Планер** (`/planner/:boardId/sprint/:sprintId`) — рабочая область. Вкладки в шапке (`SprintTab` в [`components/PageHeader.tsx`](../components/PageHeader.tsx), query `?tab=`):
   - **Бэклог** (`backlog`) — [`features/backlog/components/BacklogPage.tsx`](../features/backlog/components/BacklogPage.tsx)
   - **Доска** (`board`, по умолчанию) — свимлейн / канбан, [`features/sprint/components/SprintPlanner/SprintPlannerView.tsx`](../features/sprint/components/SprintPlanner/SprintPlannerView.tsx)
   - **Диаграмма сгорания** (`burndown`) — [`features/burndown/components/BurndownChart.tsx`](../features/burndown/components/BurndownChart.tsx)
   - **Ретро** (`retro`) — [`features/retro/components/RetroPage.tsx`](../features/retro/components/RetroPage.tsx)
   - **Метрики** (`metrics`) — [`features/sprint-metrics/components/SprintMetricsPage.tsx`](../features/sprint-metrics/components/SprintMetricsPage.tsx)
3. **Админка** (`/admin/*`) — вне этого руководства.

### Доска (вкладка `board`)

- Панель управления сверху: селектор спринта, отмена/повтор плана, перезагрузка задач, режим отображения (**По исполнителям** / **По фичам** / **Канбан**), кнопка сайдбара.
- Свимлейн ([`features/swimlane/`](../features/swimlane/), карточка — [`features/task/components/TaskBar/`](../features/task/components/TaskBar/)): строка на исполнителя, колонки — дни спринта.
- Правый клик по карточке — контекстное меню ([`features/context-menu/components/ContextMenu.tsx`](../features/context-menu/components/ContextMenu.tsx)): статус, исполнитель, оценка, родитель, перенос в спринт, «Удалить из плана», «Убрать из спринта», «Информация о задаче».

### Сайдбар доски

Вкладки ([`features/sidebar/components/SidebarTabContent.tsx`](../features/sidebar/components/SidebarTabContent.tsx)), порядок и видимость настраиваются:

- **Задачи** — незапланированные задачи спринта, поиск, фильтр по статусу, группировка, «Автоплан», «Вернуть все»
- **Бэклог** — задачи вне спринта
- **Спринт** — цели Delivery / Discovery, запуск и завершение спринта
- **Дейли**, **Метрики**

## Пользовательские истории и тест-кейсы

### 1. Выбор доски

1. **TC-001: Страница выбора доски**
   - **Шаги**: открыть приложение без сохранённой доски (или перейти на `/select-board`).
   - **Ожидаемый результат**: отображается список досок организации из подключённого трекера.

2. **TC-002: Выбор доски**
   - **Шаги**: кликнуть на доску, дождаться загрузки.
   - **Ожидаемый результат**:
     - Переход на `/planner/:boardId/sprint/:sprintId`, открыта вкладка «Доска»
     - Выбран спринт со статусом `in_progress`; если такого нет — первый в списке
     - В шапке — название доски

3. **TC-003: Смена доски** **[демо]**
   - **Шаги**: в шапке открыть селектор доски, выбрать другую.
   - **Ожидаемый результат**: загружаются спринты новой доски, выбранный спринт обновляется.

---

### 2. Спринты и вкладки

1. **TC-010: Переключение вкладок** **[демо]**
   - **Шаги**: по очереди нажать «Бэклог», «Доска», «Диаграмма сгорания», «Ретро», «Метрики».
   - **Ожидаемый результат**: открывается соответствующий экран; на боевом контуре в URL меняется `?tab=`.

2. **TC-011: Выбор спринта** **[демо]**
   - **Шаги**: на «Доске» в селекторе спринта выбрать другой спринт.
   - **Ожидаемый результат**: загружаются задачи спринта, перестраиваются свимлейны и сайдбар; на боевом контуре меняется `sprintId` в URL.

3. **TC-012: Режимы доски** **[демо]**
   - **Шаги**: в селекторе «Режим отображения» выбрать «По исполнителям», «По фичам», «Канбан».
   - **Ожидаемый результат**: свимлейн по людям, свимлейн по фичам, канбан-колонки по статусам. В канбане нет кнопок отмены/повтора плана.

---

### 3. Планирование на свимлейне

1. **TC-020: Отображение свимлейна** **[демо]**
   - **Шаги**: открыть «Доску» в режиме «По исполнителям».
   - **Ожидаемый результат**: строка на каждого исполнителя, 10 рабочих дней, в каждом дне 3 ячейки; выходные заштрихованы.

2. **TC-021: Перетаскивание задачи из сайдбара** **[демо]**
   - **Шаги**: на вкладке сайдбара «Задачи» взять задачу и перетащить в ячейку свимлейна исполнителя.
   - **Ожидаемый результат**: карточка появляется в выбранном месте, задача уходит из списка незапланированных.

3. **TC-022: Перемещение между исполнителями и днями** **[демо]**
   - **Шаги**: перетащить карточку в строку другого исполнителя, затем на другой день.
   - **Ожидаемый результат**: карточка перемещается, позиция обновляется.

4. **TC-023: Изменение длительности** **[демо]**
   - **Шаги**: потянуть за край карточки.
   - **Ожидаемый результат**: длительность меняется, карточка не выходит за границы спринта.

5. **TC-024: Возврат в сайдбар** **[демо]**
   - **Шаги**: перетащить карточку со свимлейна на сайдбар **или** в контекстном меню выбрать «Удалить из плана».
   - **Ожидаемый результат**: карточка исчезает со свимлейна, задача снова в списке незапланированных.

6. **TC-025: Отмена и повтор** **[демо]**
   - **Шаги**: переместить карточку, нажать «Отменить», затем «Повторить» в панели управления.
   - **Ожидаемый результат**: позиция откатывается и возвращается.

7. **TC-026: Сохранение позиций**
   - **Шаги**: переместить карточку, перезагрузить страницу.
   - **Ожидаемый результат**: карточка на новом месте (позиции хранятся в PostgreSQL).

---

### 4. Бэклог

1. **TC-030: Отображение бэклога** **[демо]**
   - **Шаги**: открыть вкладку «Бэклог».
   - **Ожидаемый результат**: колонка «Бэклог», колонки спринтов, список «Завершенные спринты»; работают поиск, фильтры по статусу и исполнителям.

2. **TC-031: Из бэклога в спринт** **[демо]**
   - **Шаги**: перетащить задачу из колонки «Бэклог» в колонку спринта.
   - **Ожидаемый результат**: задача появляется в спринте и пропадает из бэклога.

3. **TC-032: Из спринта в бэклог** **[демо]**
   - **Шаги**: перетащить задачу из колонки спринта в колонку «Бэклог».
   - **Ожидаемый результат**: задача уходит из спринта и появляется в бэклоге.

4. **TC-033: Массовый перенос** **[демо]**
   - **Шаги**: выделить несколько задач, в панели массовых действий выбрать «В спринт» или «В бэклог».
   - **Ожидаемый результат**: задачи перенесены, тост с количеством.

---

### 5. Цели спринта (вкладка сайдбара «Спринт»)

1. **TC-040: Отображение целей** **[демо]**
   - **Шаги**: на «Доске» открыть сайдбар, вкладка «Спринт».
   - **Ожидаемый результат**: блоки «Цели Delivery» и «Цели Discovery», бейдж прогресса на вкладке.

2. **TC-041: Отметка цели** **[демо]**
   - **Шаги**: кликнуть чекбокс цели.
   - **Ожидаемый результат**: цель отмечена, прогресс обновлён.

3. **TC-042: Добавление цели** **[демо]**
   - **Шаги**: «Добавить цель», ввести текст, Enter.
   - **Ожидаемый результат**: цель появляется в списке.

4. **TC-043: Редактирование цели** **[демо]**
   - **Шаги**: кликнуть по тексту цели, изменить, Enter (Esc — отмена).
   - **Ожидаемый результат**: текст обновлён.

5. **TC-044: Удаление цели** **[демо]**
   - **Шаги**: кнопка «Удалить» у цели, подтвердить «Удалить эту цель?».
   - **Ожидаемый результат**: цель удалена.

6. **TC-045: Сохранение целей**
   - **Шаги**: выполнить TC-041…TC-044, перезагрузить страницу.
   - **Ожидаемый результат**: изменения на месте (таблица `sprint_goals` в PostgreSQL, не трекер).

---

### 6. Задачи

1. **TC-050: Информация о задаче** **[демо]**
   - **Шаги**: правый клик по карточке → «Информация о задаче».
   - **Ожидаемый результат**: открывается боковая панель: название, описание, статус, исполнитель, story points / test points.

2. **TC-051: Изменение статуса**
   - **Шаги**: правый клик по карточке → «Изменить статус» → выбрать переход (или выбрать статус в панели информации о задаче).
   - **Ожидаемый результат**: статус обновлён в интерфейсе и в трекере.

3. **TC-052: Изменение оценки**
   - **Шаги**: правый клик → «Изменить оценку», ввести story points / test points.
   - **Ожидаемый результат**: оценка обновлена в интерфейсе и в трекере.

4. **TC-053: Перенос в другой спринт**
   - **Шаги**: правый клик → «Перенести в другой спринт» → выбрать спринт, подтвердить.
   - **Ожидаемый результат**: задача пропадает из текущего спринта и появляется в выбранном.

---

### 7. Диаграмма сгорания

1. **TC-070: Отображение графика** **[демо]**
   - **Шаги**: открыть вкладку «Диаграмма сгорания».
   - **Ожидаемый результат**: график с линией «Плановая сходимость» и остатком SP/TP, плитки метрик.

2. **TC-071: Смена спринта** **[демо]**
   - **Шаги**: в селекторе спринта на этой вкладке выбрать другой спринт.
   - **Ожидаемый результат**: график перестраивается.

3. **TC-072: Тултип дня** **[демо]**
   - **Шаги**: навести на точку графика, кликнуть.
   - **Ожидаемый результат**: тултип с метриками дня и ченжлогом закрепляется; закрывается кнопкой «Закрыть тултип».

---

### 8. Ретро

1. **TC-080: Отображение доски ретро** **[демо]**
   - **Шаги**: открыть вкладку «Ретро», выбрать спринт.
   - **Ожидаемый результат**: колонки ретро по шаблону организации, блок фактов спринта (кнопка «Скрыть показатели» / «Показать показатели»).

2. **TC-081: Карточки** **[демо]**
   - **Шаги**: в колонке «Добавить карточку», ввести текст; затем удалить карточку.
   - **Ожидаемый результат**: карточка появляется и удаляется.

3. **TC-082: Колонки** **[демо]**
   - **Шаги**: «Добавить колонку», переименовать, сдвинуть влево/вправо, удалить (подтверждение).
   - **Ожидаемый результат**: колонки меняются соответственно.

4. **TC-083: Комментарии** **[демо]**
   - **Шаги**: открыть комментарии карточки, отправить комментарий, удалить его.
   - **Ожидаемый результат**: комментарий появляется и удаляется, счётчик обновляется.

5. **TC-084: Сохранение ретро**
   - **Шаги**: изменить доску, перезагрузить страницу.
   - **Ожидаемый результат**: изменения на месте (доска хранится в PostgreSQL, `app/api/sprints/[sprintId]/retro`).

## Критерии успешного тестирования

### Функциональные

- Задачи перетаскиваются между сайдбаром, исполнителями и днями
- Позиции, цели и ретро сохраняются после перезагрузки (боевой контур)
- Статусы, оценки и перенос в спринт синхронизируются с трекером
- Бэклог показывает задачи вне спринтов, перенос в обе стороны работает

### Нефункциональные

- Перетаскивание без заметных лагов
- Ошибки показываются пользователю (тосты), консоль браузера без необработанных ошибок

## Инструкции для агентов MCP

### Подготовка

1. **Запуск**: уже запущенный dev-сервер (`pnpm docker:dev` → `http://localhost:3000`) или `pnpm dev`. Установка и переменные окружения (`.env` из `env.example`) — [INSTALL.md](./INSTALL.md).
2. **Демо**: для кейсов **[демо]** достаточно открыть `http://localhost:3000/demo/planner`, логин и `DEMO_*` не нужны.
3. **Боевой контур**: логин, подключённый трекер (Yandex Tracker или Jira), доступная PostgreSQL.

### Процесс

1. Навигация через браузерный MCP (например, Playwright), скриншот на каждом кейсе, проверка консоли.
2. Для каждого кейса: шаги → проверка ожидаемого результата → ✅ / ❌; при ❌ — скриншот и описание.
3. Для боевого контура дополнительно: изменения доходят до трекера, после перезагрузки позиции/цели/ретро на месте.
