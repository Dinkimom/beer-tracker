# Beer Tracker (Sprint Manager) — обзор проекта

Единый справочник: **что это**, **для кого**, **какие экраны и функции**, **как устроено технически**.

Актуальная версия приложения: **0.2.1**.  
Связанные документы: [CAPABILITIES.md](./CAPABILITIES.md), [ARCHITECTURE.md](../ARCHITECTURE.md), [README.md](../README.md), [DOCUMENTATION_INDEX.md](./DOCUMENTATION_INDEX.md).

## 1. Что это

**Beer Tracker** (в UI — «Трекер» / Sprint Manager) — веб-приложение для **планирования спринтов поверх внешнего issue tracker**: **Яндекс Трекер** или **Jira** (Cloud / Data Center). Один провайдер на инстанс — см. [ISSUE_TRACKERS.md](./ISSUE_TRACKERS.md).

Оно **не заменяет** трекер как систему учёта задач. Задачи, статусы, спринты и доски живут во внешнем трекере; приложение даёт визуальный планер (свимлейны, бэклог, SLA-баги, цели, burndown) с сохранением позиций и планов в собственной PostgreSQL. Режим занятости («По задачам») deprecated и скрыт из переключателя видов.

## 2. Для кого и зачем

| Аудитория | Зачем |
|-----------|--------|
| Команды разработки / QA | Планировать спринт по дням и людям, видеть загрузку, переносить задачи из бэклога |
| Тимлиды / PM | Цели спринта, метрики, burndown |
| Админы организации | Организации, команды, роли, подключение issue tracker, синхронизация снимков |
| Онбординг / community | Локальный или on-prem запуск community-сборки |

**Главная ценность:** быстрый визуальный план спринта с DnD, синхронизацией с подключённым трекером и учётом доступности людей (отпуска, техспринты, календарь).

## 4. Возможности по доменам

### 4.1. Планер спринта (доска)

Визуальное планирование на **10 рабочих дней**, каждый день — **3 части** (утро / день / вечер) → 30 ячеек на спринт.

**Режимы просмотра (`viewMode`):**

| Режим | Что показывает |
|-------|----------------|
| **full / swimlanes** | Свимлейны по разработчикам/тестировщикам, карточки на таймлайне |
| **compact** | Компактные свимлейны |
| **kanban** | Канбан-представление |
| **occupancy** | Deprecated: скрыта из переключателя; код сохранён |

**Функции:**

- Drag & Drop задач между свимлейнами и днями
- Изменение длительности (resize) карточек/фаз
- Сохранение позиций в БД (`task_positions`, опционально сегменты `task_position_segments`)
- **Дробление фазы на отрезки** (вкл/выкл ячеек) — не сплошной блок, а несколько сегментов
- Авторасстановка задач по исполнителям
- Связи между задачами (стрелки, `task_links`)
- Комментарии / стикеры на таймлайне (`sprint_comments`)
- Контекстное меню: статусы, оценки SP/TP, создание связанных задач
- Учёт работы (модалка списания)
- Старт / финиш спринта (модалки с проверками)
- Оценка спринта (score / SP·TP метрики на UI)
- Занятость календаря на свимлейне (CalDAV, настройки пользователя)
- События GitLab (MR / pipeline) на карточках задач — где подключено
- Темы: светлая / тёмная / новогодняя; локализация **ru / en**

**Ограничения модели:** один активный спринт в планере; одна доска за раз; сетка 10×3.

### 4.2. Сайдбар спринта

Вкладки (часть можно скрыть в настройках):

| Вкладка | Назначение |
|---------|------------|
| **Задачи** | Задачи текущего спринта: фильтры, группировка, поиск, DnD на доску |
| **Невалидные** | Задачи с проблемами валидации планирования |
| **Спринт (цели)** | Чеклисты целей Delivery / Discovery, roadmap-блок спринта |
| **Метрики** | Объём по статусам и исполнителям |
| **Релизы** | Задачи, готовые к релизу |
| **Бэклог** | Задачи вне спринта (в контексте сайдбара) |
| **Баги** | Очередь открытых **SLA-багов** команды доски |

#### Вкладка «Баги» (SLA)

- Открытые bug P0–P4 продуктовой команды доски; уже стоящие на свимлейне скрываются
- Секции: **Брать сейчас** → **Разобрать** → **Следить** → **Обычные**
- Сигналы риска на карточках, метрики SLA, heatmap обращений HD (overseer)
- Сводка и графики по приоритетам  
Подробнее: [SLA_BUGS_TAB.md](./SLA_BUGS_TAB.md), [SLA_BUGS_SIGNALS.md](./SLA_BUGS_SIGNALS.md).

### 4.3. Бэклог (вкладка страницы)

- Список задач, не включённых в спринт
- Фильтры (статус, тип, исполнитель, теги), поиск, группировка, пагинация
- Перенос в спринт (в т.ч. DnD)

---

### 4.4. Burndown

- Идеальная и фактическая кривые выгорания
- Метрики оставшихся / общих SP и TP
- Переключение спринтов, подсказки по точкам графика (Recharts)

---

### 4.5. Цели спринта

- Чеклисты целей (синхронизация с Tracker)
- Добавление / редактирование / выполнение / отметка выполнения
- Прогресс «N/M выполнено»
- Разделение delivery / discovery в UI целей

---

### 4.6. Задачи (сквозное)

- Карточка / модалка задачи, changelog, комментарии
- Смена статусов (переходы Tracker), правка SP/TP
- Создание задач и связанных задач
- Визуальные связи на планере

---

### 4.7. Команда и доступность

- Участники из PostgreSQL (`team_members` / staff), роли developer/tester
- Мердж с исполнителями из спринта Tracker
- Видимость людей на свимлейнах
- События недоступности: отпуска, техспринты по платформам

### 4.8. Админка (`/admin`)

| Раздел | Путь | Что делает |
|--------|------|------------|
| Организация | `/admin/org` | Tenant: создание/переименование организации |

Доступ к пунктам зависит от роли (например, sync — при включённом экспортёре; тимлид может видеть команды).

## 5. Интеграции и данные

```text
Пользователь (браузер)
    │  токен трекера (localStorage) + сессия продукта + X-Organization-Id
    ▼
Next.js (UI + /api/*)
    ├── Issue tracker API      — Yandex Tracker или Jira (спринты, доски, мутации, часть чтений)
    ├── PostgreSQL             — планер, tenant, staff, issue_snapshots
    │                            (снимки задач для бэклога и списков)
    └── Redis + BullMQ (опц.)  — фоновый sync-worker
```

**Аутентификация к трекеру:** пользовательский токен в браузере (`X-Tracker-Token`; для Jira Cloud — ещё email); опционально серверный fallback в env. Без учётки — редирект на `/auth-setup`. Провайдер инстанса: [ISSUE_TRACKERS.md](./ISSUE_TRACKERS.md).

**Плановый sync:** `POST /api/internal/sync/tick` + `pnpm sync-worker` при настроенном Redis.

Клиент ходит в API **только** через `lib/api/*` (`getPlannerBeerTrackerApi`), не через raw `fetch('/api/...')`.

## 7. Архитектура кода (кратко)

```text
features/ / components/ / hooks/
        → lib/api/*          (клиентский фасад)
        → app/api/**/route.ts  (тонкий HTTP: auth, Zod, статусы; без SQL)
        → lib/<domain>/        (repositories, оркестрация, SQL)
```

**Feature-домены** (`features/`): `sprint`, `task`, `sidebar`, `swimlane`, `backlog`, `burndown`, `sla-bugs`, `comments`, `context-menu`, `account`, `board`, `developers`-логика, `qa`, `admin`, `gitlab`, …  
Deprecated (не развивать): `feature-planner`, `quarterly-planning-v2`.

**Состояние планера:**

- React Query — списки задач спринта, спринты, доски
- MobX `TaskPositionsStore` / `SprintPlannerUiStore` — позиции и преходящий UI
- Локальный стейт + debounce — связи, комментарии, порядок occupancy

Подробно: [ARCHITECTURE.md](../ARCHITECTURE.md), [STRUCTURE.md](./STRUCTURE.md), [AGENTS.md](../AGENTS.md).

## 10. Запуск и качество

```bash
pnpm install
cp env.example .env          # POSTGRES_*, при необходимости Redis, секреты
docker compose up -d db redis
pnpm dev
```

Обязательные проверки перед сдачей задачи (см. AGENTS.md):

```bash
pnpm typecheck && pnpm lint && pnpm test && pnpm lint:unused
```

Дополнительно: `pnpm storybook`, `pnpm build`, `pnpm sync-worker`.
