# Beer Tracker — обзор проекта

Единый справочник: **что это**, **для кого**, **какие экраны и функции**, **как устроено технически**.

Актуальная версия приложения: **1.24.0** (см. [CHANGELOG.md](../CHANGELOG.md)).  
Связанные документы: [CAPABILITIES.md](./CAPABILITIES.md), [ARCHITECTURE.md](../ARCHITECTURE.md), [README.md](../README.md), [DOCUMENTATION_INDEX.md](./DOCUMENTATION_INDEX.md).

---

## 1. Что это

**Beer Tracker** (в UI — «Трекер») — веб-приложение для **планирования спринтов поверх внешнего issue tracker**: **Яндекс Трекер** или **Jira** (Cloud / Data Center). Провайдер выбирается на организацию и хранится в БД — см. [ISSUE_TRACKERS.md](./ISSUE_TRACKERS.md).

Оно **не заменяет** трекер как систему учёта задач. Задачи, статусы, спринты и доски живут во внешнем трекере; приложение даёт визуальный планер (свимлейн, бэклог, burndown, ретро, метрики, цели) с сохранением позиций, заметок и планов в собственной PostgreSQL, а также MCP-доступ для внешнего агента (Claude, Cursor…), который предлагает правки плана.

## 2. Для кого и зачем

| Аудитория | Зачем |
|-----------|--------|
| Команды разработки / QA | Планировать спринт по дням и людям, видеть загрузку, переносить задачи из бэклога |
| Тимлиды / PM | Цели спринта, метрики, burndown, ретро |
| Админы организации | Организации, команды, роли, подключение issue tracker, синхронизация снимков |
| Онбординг / community | Локальный или on-prem запуск community-сборки |

**Главная ценность:** быстрый визуальный план спринта с DnD, синхронизацией с подключённым трекером и учётом доступности людей (отпуска, техспринты, календарь).

## 4. Возможности по доменам

### 4.1. Планер спринта (доска)

Длина спринта — по датам спринта в трекере; рабочий день делится на **2–4 слота** (по умолчанию 3, настройка организации в `/admin/planner`). Выходные и праздники страны организации заштрихованы.

**Режимы просмотра (`viewMode`):**

| Режим | Что показывает |
|-------|----------------|
| **full / compact** | «По исполнителям»: свимлейн по разработчикам/тестировщикам (обычный и компактный) |
| **features** | «По фичам»: строка = родитель (фича/стори) |
| **kanban** | Канбан по статусам |

**Функции:**

- Drag & Drop задач между дорожками и днями, превью места и снап к сетке
- Изменение длительности (resize) карточек/фаз
- Сохранение позиций в БД (`task_positions`, опционально сегменты `task_position_segments`)
- **Дробление фазы на отрезки** — не сплошной блок, а несколько сегментов
- **Слои строк**: автосортировка или ручная раскладка задач и заметок (`swimlane_card_layers`)
- Авторасстановка задач по исполнителям
- Связи между задачами (стрелки, `task_links`)
- Заметки на свимлейне (`comments`): WYSIWYG-редактор (markdown внутри), реакции, фото, диаграммы Excalidraw, виджеты
- План против факта: таймлайн факта по changelog, план на старте работы (`sprint_plan_captures`), бейджи переноса
- Черновик плана, undo/redo, перенос карточки в другой спринт
- Контекстное меню: статусы, оценки SP/TP, исполнитель, родитель, создание связанных задач
- Учёт работы (модалка списания)
- Финиш спринта (модалка с проверками), проверки старта — во вкладке целей
- Оценка спринта (score / SP·TP метрики на UI)
- Доступность (отпуска, техспринты и др.) и занятость календаря (CalDAV) на дорожках
- Совместная работа: присутствие участников, realtime-обновления (SSE), таймер спринта
- Темы: светлая / тёмная / новогодняя; локализация **ru / en**

**Ограничения модели:** один спринт в планере; одна доска за раз.

### 4.2. Сайдбар спринта

Вкладки (часть можно скрыть в настройках):

| Вкладка | Назначение |
|---------|------------|
| **Задачи** | Задачи текущего спринта: фильтры, группировка, поиск, DnD на доску |
| **Невалидные** | Задачи с проблемами валидации планирования |
| **Спринт (цели)** | Цели Delivery / Discovery, проверки старта спринта |
| **Дейли** | Заметки по дням спринта (хранятся только в браузере) |
| **Метрики** | Объём по статусам и исполнителям |
| **Бэклог** | Задачи вне спринта (в контексте сайдбара) |

---

### 4.3. Бэклог (вкладка страницы)

- Колонки бэклога и спринтов доски, архив завершённых спринтов
- Фильтр по исполнителю, поиск, «показать ещё»
- Перенос в спринт (DnD или массово), создание спринта

---

### 4.4. Burndown

- Идеальная и фактическая кривые выгорания
- Метрики оставшихся / общих SP и TP
- Подсказки по точкам графика с изменениями задач (Recharts)

---

### 4.5. Цели спринта

- Цели хранятся в PostgreSQL приложения (`sprint_goals`), не в трекере
- Добавление / редактирование / отметка выполнения / удаление
- Прогресс «N/M выполнено»
- Разделение delivery / discovery в UI целей
- Агент может предложить текст целей (превью «Принять» / «Отклонить»)

---

### 4.6. Задачи (сквозное)

- Панель задачи (`TaskInfoSidebar`): описание, мета-поля, переходы, связи; changelog
- Смена статусов (переходы трекера, экран перехода и обязательные поля), правка SP/TP
- Создание задач и связанных задач, быстрое добавление с поиском по трекеру
- Настраиваемые слоты полей на карточке
- Визуальные связи на планере

---

### 4.7. Команда и доступность

- Участники из PostgreSQL (`team_members` / staff), роли developer/tester
- Мердж с исполнителями из спринта Tracker
- Видимость людей на свимлейнах
- События недоступности (`board_availability_events`): отпуска, больничные, дежурства, техспринты
- Средняя velocity в заголовке дорожки

| Раздел | Путь | Что делает |

### 4.9. Настройки пользователя (модалка)

- Токен / учётка подключённого issue tracker (Yandex ID OAuth, Jira Cloud OAuth или Jira PAT / API token)
- Календарь (CalDAV) и показ занятости на свимлейне
- Общие и планирование: функции UI, отображение, видимость табов сайдбара
- «Что нового» (из `CHANGELOG.md`) по клику на версию
- Язык интерфейса (ru/en), тема

---

### 4.10. Ретро

- Доска ретроспективы спринта: колонки, заметки, фото, комментарии, реакции с голосами
- Факты спринта рядом с доской; шаблон колонок — `/admin/retro`

---

### 4.11. Метрики

- Дашборд доски по кварталу: say/do, velocity, cycle time, перенос, доля багов
- Графики, таблица по спринтам, фильтры команды и периода, экспорт CSV

---

### 4.12. Агент и MCP

- Удалённый MCP `/api/mcp` (OAuth 2.1): контекст спринта, поиск задач и спринтов, ретро — [SPRINT_CONTEXT.md](./SPRINT_CONTEXT.md)
- Запись только через `propose_plan_patch` → `apply_plan_patch`; предложения видны на доске черновиком и принимаются / отклоняются в UI
- Сессии агента в планере (кнопка ✨): чат, `@`-упоминания, скиллы по «/», вопросы с вариантами
- Локальный мост `pnpm agent-bridge` (`apps/agent-bridge/`) запускает Claude CLI для ожидающей сессии

## 5. Интеграции и данные

```text
Пользователь (браузер)
    │  токен трекера (localStorage) + сессия продукта + X-Organization-Id
    ▼
Next.js (UI + /api/*)
    ├── Issue tracker API      — Yandex Tracker или Jira (спринты, доски, мутации, часть чтений)
    ├── PostgreSQL             — планер, tenant, staff, issue_snapshots
    │                            (снимки задач для бэклога и списков)
    ├── Redis + BullMQ (опц.)  — фоновый sync-worker (apps/sync-worker/)
    └── S3 (опц.)              — фото и файлы планера
```

**Аутентификация к трекеру:** пользовательский токен в браузере (`X-Tracker-Token`; для Jira Cloud OAuth — ещё `X-Tracker-Cloud-Id`). Токен организации для sync хранится зашифрованно в БД, env-fallback нет. Без учётки — редирект на `/auth-setup`. Провайдер организации: [ISSUE_TRACKERS.md](./ISSUE_TRACKERS.md).

**Плановый sync:** `POST /api/internal/sync/tick` + `pnpm sync-worker` при настроенном Redis.

Клиент ходит в API **только** через `lib/api/*` (`getPlannerBeerTrackerApi`), не через raw `fetch('/api/...')`.

## 7. Архитектура кода (кратко)

```text
features/ / components/ / hooks/
        → lib/api/*          (клиентский фасад)
        → app/api/**/route.ts  (тонкий HTTP: auth, Zod, статусы; без SQL)
        → lib/<domain>/        (repositories, оркестрация, SQL)
```

**Feature-домены** (`features/`): `sprint`, `swimlane`, `task`, `sidebar`, `comments`, `backlog`, `burndown`, `retro`, `sprint-metrics`, `context-menu`, `notifications`, `account`, `board`, `qa`, `admin`, `widgets`, …

**Состояние планера:**

- React Query — списки задач спринта, спринты, доски
- MobX `TaskPositionsStore` / `SprintPlannerUiStore` — позиции и преходящий UI
- Локальный стейт + debounce — связи, комментарии

Подробно: [ARCHITECTURE.md](../ARCHITECTURE.md), [STRUCTURE.md](./STRUCTURE.md), [AGENTS.md](../AGENTS.md).

## 10. Запуск и качество

Готовые образы: [`dinkimom/beer-tracker`](https://hub.docker.com/r/dinkimom/beer-tracker) и [`dinkimom/beer-tracker-sync-worker`](https://hub.docker.com/r/dinkimom/beer-tracker-sync-worker) (теги `latest` и версия релиза, `linux/amd64` + `linux/arm64`).

```bash
cp env.example .env
docker compose -f docker-compose.yml -f docker-compose.hub.yml up -d
```

Разработка из исходников:

```bash
pnpm install
cp env.example .env          # POSTGRES_*, при необходимости Redis, секреты
docker compose up -d db redis
pnpm dev
```

Обязательные проверки перед сдачей задачи (см. AGENTS.md):

```bash
pnpm typecheck && pnpm lint && pnpm test && pnpm lint:unused
```

Дополнительно: `pnpm storybook`, `pnpm build`, `pnpm sync-worker`, `pnpm agent-bridge`.
