# Возможности приложения Beer Tracker

## Обзор

**Beer Tracker** — веб-приложение для планирования и управления спринтами поверх **Яндекс Трекера** или **Jira**. Задачи раскладываются по дням и людям на свимлейне; рядом — бэклог, диаграмма сгорания, ретро и метрики, а внешний агент (Claude, Cursor…) может предлагать план через MCP. Провайдер трекера выбирается на организацию: [ISSUE_TRACKERS.md](./ISSUE_TRACKERS.md).

Вкладки страницы спринта (`?tab=`): **Бэклог**, **Доска** (по умолчанию), **Диаграмма сгорания**, **Ретро**, **Метрики**. Без логина в трекер свимлейн, бэклог, диаграмму сгорания и ретро можно посмотреть на `/demo/planner` (фикстуры).

## Основные возможности

### 1. Планирование спринтов

Визуальная раскладка задач спринта по дням и исполнителям.

**Сетка:**
- Длина спринта — по датам спринта в трекере; выходные и праздники (календарь страны организации) заштрихованы
- День делится на **2–4 слота** (по умолчанию 3), шкала и соответствие SP ↔ слоты настраиваются в `/admin/planner`
- Если план выходит за последний день, таймлайн расширяется и переполнение помечается

**Виды доски:**
- **По исполнителям** — свимлейн, дорожка на каждого разработчика/тестировщика (обычный и компактный)
- **По фичам** — строка = родитель (фича/стори), исполнитель на карточке
- **Канбан** — колонки по статусам; дроп в колонку с несколькими статусами предлагает выбрать переход

**Функции свимлейна:**
- **Drag & Drop** с превью места и снапом к сетке; перенос между дорожками и в сайдбар
- **Изменение длительности** (resize) и **дробление фазы на отрезки** — см. [PHASE_SEGMENTS_FEATURE.md](./PHASE_SEGMENTS_FEATURE.md)
- **Слои строк**: автосортировка или ручная раскладка задач и заметок по строкам (переключатель «Автосортировка» в меню слоёв; ручные слои сохраняются в спринте и видны команде)
- **Авторасстановка** задач по исполнителям
- **Связи** между задачами (стрелки), настройка видимости связей
- **План против факта**: таймлайн факта по changelog, якорь «план на старте работы», бейджи переноса и выросшей стоимости
- **Черновик плана** — правки можно сохранить или отменить; undo/redo (`Ctrl`/`⌘+Z`)
- **Запланировать в другом спринте** — перенос карточки или заметки черновиком в целевой спринт
- **Доступность**: отпуска, больничные, дежурства, техспринты — чипы на дорожке, правка в поповере
- **Занятость календаря** (CalDAV) отдельной дорожкой
- Совместная работа в реальном времени: аватары присутствия, цвет участника, общий таймер спринта
- Онбординг-тур по планеру

**Компоненты:**
- `SprintPlanner` (`features/sprint/components/SprintPlanner.tsx`) — контейнер планера
- `Swimlane` (`features/swimlane/components/Swimlane.tsx`) — свимлейн
- `TaskCard`, `TaskBar` (`features/task/components/`) — карточка задачи
- `Sidebar` (`features/sidebar/components/Sidebar.tsx`) — боковая панель

### 2. Управление бэклогом

Вкладка «Бэклог»: задачи вне спринта и колонки спринтов доски.

**Функции:**
- **Колонки спринтов** и бэклога, архив завершённых спринтов
- **Фильтрация** — по исполнителю и др., поиск по названию или ключу
- **Перенос в спринт** — перетаскиванием или массово (выделение + меню спринта)
- **Создание спринта** из бэклога
- Разбивка объёма по SP/TP, подгрузка «показать ещё»

**Компоненты:**
- `BacklogPage` — вкладка бэклога
- `BacklogTab` — вкладка бэклога в сайдбаре планера

### 3. Ретроспектива

Вкладка «Ретро»: доска ретроспективы спринта.

**Функции:**
- Колонки с карточками-заметками, фото-карточки, комментарии к карточкам, реакции с голосами
- Автор карточки, факты спринта рядом с доской
- Шаблон колонок организации — `/admin/retro`
- Доска доступна агенту через MCP (`get_retro_board` / `apply_retro_board`)

**Компоненты:** `RetroPage`, `RetroBoardView` (`features/retro/components/`)

### 4. Burndown Chart

Визуализация прогресса спринта через график выгорания.

**Функции:**
- **График выгорания** — идеальная и фактическая кривые по SP и TP
- **Метрики** — общий и оставшийся объём SP/TP
- **Подсказки по точкам** — с изменениями задач за день, закрепляемый тултип

**Компоненты:**
- `BurndownChart` — вкладка диаграммы
- `BurndownChartMetricsPanel` — метрики спринта

### 5. Цели спринта

Цели спринта в двух списках: **Delivery** и **Discovery**.

**Функции:**
- Добавление, редактирование, отметка выполнения, удаление
- Прогресс «N/M выполнено»
- Проверки перед стартом спринта во вкладке целей
- Агент может предложить текст целей — превью с «Принять» / «Отклонить»
- Хранение — в PostgreSQL приложения (`sprint_goals`), не в трекере

**Компоненты:**
- `GoalsTab` — вкладка «Спринт» в сайдбаре
- `GoalItem` — элемент цели

### 6. Управление задачами

**Функции:**
- **Карточка задачи** (`TaskInfoSidebar`): описание, мета-поля, переходы, связи задач
- **Изменение статуса** через контекстное меню, с экраном перехода и обязательными полями из workflow
- **Оценки** SP/TP, исполнитель, родитель — из контекстного меню
- **Создание задач** и связанных задач, быстрое добавление с поиском по трекеру
- **Настраиваемая карточка** — слоты полей, поля трекера по имени, срок и просрочка
- **История изменений** (changelog)

**Компоненты:**
- `TaskCard` — карточка задачи
- `TaskInfoSidebar` — панель задачи
- `ContextMenu` — контекстное меню задачи

### 7. Заметки на свимлейне

**Функции:**
- Заметки (стикеры) с **WYSIWYG-редактором**: заголовки, списки, чекбоксы, упоминания; хранение — markdown
- Развёрнутый редактор заметки, цвета, реакции (✅ красит заметку), ссылки на задачи по ключу
- Фото-карточки, диаграммы Excalidraw, виджет «крестики-нолики»

**Компоненты:** `features/comments/components/` (`StickyNoteRichEditor`, `SwimlaneDiagramEditor` и др.)

### 8. Агент и MCP

**Функции:**
- Удалённый MCP-сервер `/api/mcp` (OAuth 2.1, экран согласия `/mcp/oauth/consent`) — контекст спринта, поиск задач и спринтов, ретро
- Запись только через `propose_plan_patch` → `apply_plan_patch`; предложения агента видны на доске как черновик, их принимают или отклоняют
- Сессии агента: чат в планере (кнопка ✨), `@`-упоминания, скиллы по «/», вопросы с вариантами ответа
- Локальный мост `pnpm agent-bridge` (`apps/agent-bridge/`) запускает Claude CLI, когда сессия ждёт агента

Подробнее: [SPRINT_CONTEXT.md](./SPRINT_CONTEXT.md).

### 9. Метрики спринтов

Вкладка «Метрики»: дашборд доски по кварталу — say/do, velocity, cycle time, перенос задач, доля багов; графики, таблица по спринтам, фильтры команды и периода, экспорт CSV.

**Компоненты:** `SprintMetricsPage` (`features/sprint-metrics/components/`)

### 10. Сайдбар спринта

Вкладки: **Задачи**, **Невалидные**, **Спринт** (цели), **Дейли** (заметки по дням, только в браузере), **Метрики**, **Бэклог**, **Баги** (SLA-баги — [SLA_BUGS_TAB.md](./SLA_BUGS_TAB.md)). Видимость вкладок настраивается.

### 11. Команда и доступность

**Функции:**
- Участники из PostgreSQL приложения (`team_members` / `staff`), роли и платформы
- Мердж с исполнителями из спринта трекера; видимость и порядок людей в планере
- Средняя velocity в заголовке дорожки
- События доступности хранятся в `board_availability_events`

**Компоненты:**
- `DevelopersManagement` — управление участниками в сайдбаре
- `DeveloperHeader` — заголовок дорожки

### 12. Выбор доски

**Функции:**
- Страница `/select-board` и селектор доски в шапке
- Ссылка на спринт: `/planner/[boardId]/sprint/[sprintId]`

**Компоненты:**
- `BoardSelector` — селектор доски

### 13. Учёт работы

Модалка учёта работы по задачам спринта (`AccountWorkModal`).

### 14. Уведомления

Колокольчик в шапке: упоминания в заметках, смена исполнителя и др. (`features/notifications/`).

## Не в продукте

Планировщик эпиков / фич, квартальный план и режим «Занятость» удалены из кода. Сохранённый в браузере режим `occupancy` сбрасывается на свимлейн. См. [steering/product.md](./steering/product.md).

## Технические возможности

### Интеграции

1. **Yandex Tracker / Jira API** — спринты, доски, мутации задач (статусы, оценки, исполнитель, спринт), связи
2. **PostgreSQL (`issue_snapshots`, `issue_changelog_events`)** — снимки задач из sync: бэклог, карточка задачи, burndown, changelog
3. **PostgreSQL приложения** — tenant, staff/teams, позиции, связи, заметки, цели, ретро, сессии агента
4. **Redis + BullMQ** (опционально) — фоновая синхронизация (`apps/sync-worker/`)
5. **S3-совместимое хранилище** (опционально) — фото и файлы планера
6. **CalDAV** — занятость календаря, где настроен

### Безопасность

- **Пользовательские токены** — каждый работает под своим токеном трекера (Yandex ID OAuth, Atlassian OAuth, Jira PAT / API token)
- **Хранение** — токен пользователя в браузере (localStorage); токен организации для sync — зашифрованно в БД, без env-fallback
- Сессия продукта и организация (`X-Organization-Id`) для всех `/api/*`

### Производительность

- Пул соединений PostgreSQL
- Кэш ответов трекера на инстансе и в React Query
- Graceful degradation при ошибках интеграций

## Пользовательский интерфейс

- Темы: светлая, тёмная, новогодняя; языки ru / en
- **Radix UI** (Dialog, Popover, Tooltip), **Tailwind CSS 4**
- **dnd-kit** — drag-and-drop
- **Recharts** — графики, **react-xarrows** — стрелки связей
- **Tiptap** — редакторы заметок и описания задачи
- PWA (установка, офлайн-страница)

## Архитектура

Feature-based структура: домены в `features/`, серверная логика в `lib/<домен>/`, тонкие роуты в `app/api/`. Подробно: [STRUCTURE.md](./STRUCTURE.md), [ARCHITECTURE.md](../ARCHITECTURE.md).

## API

- **Клиент** → `lib/api/*` (axios) → Next.js API Routes
- **Сервер** → `/api/*`: API трекера, PostgreSQL (`lib/<домен>/*Repository.ts`)

Основные эндпоинты: `/api/sprints`, `/api/tracker`, `/api/backlog`, `/api/issues/[issueKey]`, `/api/sprint-goals`, `/api/teams/members`, `/api/mcp`. Legacy: `/api/features`.

Подробнее: [API_DOCUMENTATION.md](./API_DOCUMENTATION.md)

## База данных

### Основные таблицы планера

- `task_positions`, `task_position_segments` — позиции и отрезки фаз
- `task_links` — связи между задачами
- `comments`, `comment_reactions` — заметки на свимлейне и реакции
- `swimlane_card_layers` — ручные слои свимлейна
- `sprint_goals`, `sprint_plan_captures` — цели и план на старте
- `retro_boards`, `retro_column_templates` — ретро
- `board_availability_events` — доступность участников
- `agent_sessions`, `plan_patch_position_previews`, `plan_patch_goal_previews` — агент и его предложения

Таблицы `feature_documents*` и `quarterly_plan_v2_*` — leftover deprecated-экранов (код квартального плана удалён), не развивать. Схема: `database/init.sql` и миграции `database/*.sql`.

## Ограничения

- **Один спринт** в планере за раз
- **Одна доска** за раз
- **2–4 слота** в рабочем дне (настройка организации)

Новые возможности — только в планере спринта. См. [steering/product.md](./steering/product.md).
