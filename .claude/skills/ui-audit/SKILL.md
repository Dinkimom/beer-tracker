# Аудит интерфейса

Аргументы: `$ARGUMENTS`. Пусто или `all` — все состояния тура. Имя области (`board`, `retro`…) — состояния с
этим префиксом. Список через запятую — только эти состояния.

Регресс (скилл `regress`) отвечает на «не сломалось ли то, что работало». Аудит — на «хорошо ли сейчас»: эталона
нет, есть правила. Две опоры:

- **детекторы** ([`e2e/audit/detectors.ts`](../../../e2e/audit/detectors.ts)) — объективное: WCAG через axe,
  обрезанный текст, курсор и hover у кнопок, выключенное, которое выглядит активным, кириллица в английском UI;
- **разбор глазами** по чек-листу ниже — то, что детектор не видит: разнобой, лишние шаги, непонятный текст,
  неудачные состояния.

Dev-сервер должен отвечать: `curl -s -o /dev/null -w '%{http_code}' http://localhost:3000/demo/planner` → `200`.
Нет — попросить пользователя запустить. Второй не поднимать.

## 1. Снять состояния

```bash
pnpm e2e:tour                                         # все состояния, светлая и тёмная тема
E2E_TOUR_ONLY=board-task-info,settings pnpm e2e:tour  # выборочно
```

Тур — [`e2e/tour/states.spec.ts`](../../../e2e/tour/states.spec.ts), список `STATES`: как дойти до состояния и что
должно открыться. Выход: `e2e/.results/tour/<тема>/<состояние>.png` и `<состояние>.findings.json` (находки
детекторов в этом состоянии; перекрытия не пишутся — под меню и окнами всё перекрыто по замыслу).

Нужного состояния нет (новая фича, окно, пустое состояние) — сначала добавить запись в `STATES` по образцу
соседних (локаторы по роли и словарю `en`), потом снимать. Состояние не воспроизводится на фикстуре — данные в
`lib/demo/`.

## 2. Разобрать каждый кадр

Read каждого кадра светлой темы и тёмной — того же состояния рядом. Для каждого кадра пройти чек-лист и записать
только то, что видно на кадре и можно показать пальцем:

| Область | Что искать |
|---|---|
| **Единообразие** | Один и тот же элемент выглядит по-разному на разных экранах: кнопки, поля, бейджи статусов, заголовки панелей, отступы окон. Правила проекта: кнопки — `Button`/`HeaderIconButton`, окна — `Modal`, поповеры у точки — `AnchoredPopover`, поля — `Input` |
| **Раскладка** | Не выровнено по сетке, скачут отступы, элемент прилип к краю, пустоты, наезды, обрезка, горизонтальный скролл без нужды, узкое окно ломает вёрстку (`board-narrow`) |
| **Текст** | Непонятная или техническая формулировка, разный регистр одинаковых подписей, разные слова для одного действия, обрезано без подсказки, единицы и даты в разных форматах, опечатки |
| **Состояния** | Пустое состояние без объяснения и следующего шага (`*-search-empty`), загрузка без индикатора, ошибка без текста, выключенное без причины |
| **Тёмная тема** | Элемент пропал или нечитаем, белые вспышки, рамки не того цвета, цвет статуса неразличим, сравнить с той же сценой в светлой |
| **Иерархия и аффорданс** | Главное действие не главное визуально, кликабельное не выглядит кликабельным и наоборот, опасное действие (удалить, завершить) не отличается от обычного |
| **Обратная связь** | Действие без видимого ответа, нет подтверждения опасного, нет тоста о результате (смотреть в функциональных сценариях, не в статичном кадре) |
| **Шаги** | Чтобы сделать частое действие, нужно много кликов; одно и то же делается в двух местах по-разному |

Кадр похож на переход — полупрозрачное меню, пустая панель, элемент «на полпути», подсветка от курсора — это
сначала подозрение на тур, а не на продукт: тур ждёт покоя (`settle`), но новое состояние может ждать не тот
элемент. Переснять состояние с правильным ожиданием и только потом решать. В первом заходе так отпали
«прозрачное контекстное меню», «пустой режим по фичам» и «две активные вкладки в шапке».

Не записывать вкусовщину без опоры («кнопка некрасивая»). Опора — правило из `AGENTS.md`, соседний экран, где
то же сделано иначе, или конкретная задача пользователя, которой мешает.

## 3. Разобрать находки детекторов

Для каждого `*.findings.json`: настоящая проблема или шум детектора. Шум (детектор не понимает приём вёрстки) —
поправить детектор в `e2e/audit/detectors.ts` (и прогнать `pnpm e2e:audit` — список известных не должен
измениться без причины). Настоящая — в находки отчёта, как и разобранное глазами.

## 4. Отсеять известное

Перед записью каждой находки — поиск по [`docs/CLEANUP_BACKLOG.md`](../../../docs/CLEANUP_BACKLOG.md) и
`e2e/audit/known/`. Уже записано — не дублировать; если новый кадр добавляет место или подробность, дописать в
ту же строку.

## 5. Оценить серьёзность

| Уровень | Когда |
|---|---|
| **блокер** | Пользователь не может выполнить задачу: не нажать, не прочитать, потеря данных, падение |
| **серьёзно** | Задача выполнима, но легко ошибиться или долго: обманчивое состояние, нечитаемый контраст, опасное без подтверждения |
| **заметно** | Разнобой, непонятный текст, лишний шаг, пустое состояние без подсказки |
| **косметика** | Отступ, выравнивание, мелкий визуальный шум |

## 6. Записать

Каждая новая находка — строка в `docs/CLEANUP_BACKLOG.md` в подходящем разделе, по формату файла: что не так,
где (экран, состояние тура, файл компонента, если нашёл), серьёзность, дата. Блокеры и серьёзные — сначала
показать пользователю: возможно, их чинят сразу.

Нашёл и починил в этом же заходе — добавить проверку, чтобы не вернулось: правило детектора или кейс в
`docs/TEST_CASES.md` с автотестом (скилл `regress`).

## 7. Отчёт

```markdown
## Аудит интерфейса: <область>, <дата>
Состояний: N × 2 темы · находок: N новых (блокер N, серьёзно N, заметно N, косметика N), N уже в бэклоге
### Блокеры и серьёзные
- <что не так> — <где, состояние тура> — <почему важно>
### Заметно и косметика
- …
Шум детекторов: что поправлено в detectors.ts
Не проверено: что и почему
```

Отчёт с картинками для команды — предложить опубликовать страницей (кадры из `e2e/.results/tour/`).

## Большой заход

Полный тур — 40+ кадров; разбор глазами можно раздать субагентам по областям (доска, сайдбар и окна, остальные
вкладки). Каждому — список состояний, пути к кадрам и находкам, чек-лист из шага 2, требование «только видимое на
кадре, с опорой». Их находки — черновик: самые серьёзные перепроверить на кадре лично, потом шаги 4–7. Непроверенное
записывать с пометкой «по кадру субагента, лично не перепроверено».
